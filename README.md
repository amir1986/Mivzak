# מבזק – מבזק הידע של IBI על הבוקר

אוטומציה שמכינה בכל ערב מסחר את "מבזק הידע של IBI על הבוקר" לפי התבנית
המצורפת (`templates/mivzak_template.docx`), מפיקה קובץ Word מוכן לקריינות
ושולחת אותו במייל אל **HELLYBRACHA@GMAIL.COM**.


> **שני עותקים זהים:** אותה מערכת קיימת גם בריפו `mail-action` בתיקייה
> `mivzak-brief/` (שם ה-Secrets כבר מוגדרים). כל עותק רץ עם ה-Secrets של
> הריפו שלו; כדי שהתזמון כאן ישלח בפועל יש להגדיר את ה-Secrets גם בריפו הזה.

## לוח זמנים

| Workflow | קובץ | מתי (שעון ישראל) | תפקיד |
| --- | --- | --- | --- |
| Mivzak IBI - primary | `.github/workflows/mivzak-primary.yml` | ימים ב׳–ד׳, 23:15 | מכין ושולח את המבזק לבוקר שלמחרת |
| Mivzak IBI - backup | `.github/workflows/mivzak-backup.yml` | ימים ב׳–ד׳, 23:35 | גיבוי: רץ רק אם ה-primary לא הצליח לשלוח |

**כל הזמנים במערכת הם לפי שעון ישראל בלבד.** השעות מוגדרות ב-cron עם
`timezone: Asia/Jerusalem`, כך שהן נשארות נכונות גם במעבר בין שעון קיץ לשעון
חורף. וול סטריט נסגרת ב-23:00 שעון ישראל, ולכן ריצה מ-23:05 ואילך מסכמת את
יום המסחר של אותו תאריך בישראל, וריצה מוקדמת יותר מסכמת את יום המסחר הקודם.
גם זמן השליחה שנרשם בסמן ותאריך המבזק הם לפי שעון ישראל. שני ה-workflows
חולקים "סמן שליחה"
(`.github/state/mivzak-sent.json`) שנשמר ב-git אחרי כל שליחה מוצלחת, ולכן לא
נשלח מבזק כפול על אותו יום מסחר.

> workflows מתוזמנים רצים רק מה-branch הראשי (default branch) של הריפו.

## תזמון מדויק ב-23:15 (ולמה ה-cron לבדו לא מספיק)

ה-scheduler של GitHub Actions מפעיל ריצות מתוזמנות בחשבון הזה באיחור של
שעתיים עד חמש שעות (נמדד בכל ה-workflows כאן, בלי קשר לאזור הזמן), ולכן
המבזק יצא בסביבות 01:45 במקום 23:15. הפתרון עובד בשתי שכבות:

1. **טריגר מדויק:** ב-23:15 שעון ישראל, בימים ב׳–ד׳, Routine של Claude
   ("Mivzak brief trigger 23:15", שני רשומות: שעון קיץ ושעון חורף, כי ה-cron
   של Routines הוא ב-UTC) מעיר סשן ייעודי ("Mivzak brief trigger session")
   שדוחף commit קטן שמוסיף שורה ל-`.github/state/mivzak-trigger.log`
   עם ההודעה `Run Mivzak brief [mivzak-brief-run]`. ה-push מפעיל את
   `mivzak-primary.yml` מיד (טריגר `push` מתחיל תוך שניות, בניגוד ל-cron).
   ה-Routines מופיעים ב-claude.ai תחת Routines ואפשר להשהות אותם משם.
2. **גיבוי:** ה-cron של primary (23:15) ו-backup (23:35) נשאר. הוא רץ באיחור,
   אבל סמן השליחה גורם לו לצאת מיד כשהמבזק כבר נשלח, כך שאין כפילות.

הרצה ידנית של הטריגר: כל commit ל-main שמשנה את קובץ הטריגר ומכיל
`[mivzak-brief-run]` בהודעה מפעיל את ה-workflow; אפשר גם Run workflow רגיל.

חלופה חזקה עוד יותר, אם תרצה להיפטר מהתלות ב-Routine: שירות cron חיצוני
(למשל cron-job.org) שקורא ב-23:15 שעון ישראל ל-API של GitHub
(`POST /repos/amir1986/Mivzak/actions/workflows/mivzak-primary.yml/dispatches`
עם `{"ref":"main"}`) באמצעות fine-grained token עם הרשאת Actions: write.

> בריפו הזה הטריגר המדויק מוגדר באותו אופן (קובץ `.github/state/mivzak-trigger.log`
> והסימון `[mivzak-brief-run]`), אבל ה-Routine שדוחף את ה-commit ב-23:15 מכוון
> כרגע רק לעותק הפעיל ב-mail-action.

## מה נכנס למבזק

המשפטים הקבועים של התבנית נשמרים כמו שהם (פתיחה, "שניה הפסקה" מודגש בירוק,
וסיום "קריין"). התוכן שביניהם בנוי לפי המבזקים המקוריים של IBI, כל משפט
בשורה משלו, ומתעדכן **אך ורק לפי יום המסחר של אותו יום**:

1. **וול סטריט** – "המסחר בוול סטריט ננעל אמש במגמה חיובית." ובשורה שנייה
   שיעורי השינוי של S&P 500 ושל הנאסד"ק.
2. **מאקרו** – דו"ח התעסוקה של ADP, מדד הייצור אמפייר סטייט ונתונים מרכזיים
   אחרים, רק אם פורסמו בפועל באותו יום.
3. **ריבית** – החלטת ריבית של הפד, בנק ישראל או ה-ECB, רק אם התקבלה באותו יום.
4. **אג"ח חו"ל** – "התשואה על אג"ח מדינה ארה"ב לעשר שנים" עם השינוי בנקודות
   בסיס והרמה במאיות, כשהתשואה זזה לפחות שלוש נקודות בסיס (ניתן לשינוי דרך
   `MIVZAK_RATES_MIN_BP`).
5. **סחורות** – נפט WTI תמיד, וזהב כשהוא זז לפחות חצי אחוז (`MIVZAK_GOLD_MIN_MOVE`).
6. **עונת הדוחות** – חברות שפרסמו דוחות באותו יום, ובשורה נפרדת "בתוך כך,
   מניית החברה ...".
7. **המניה המובילה** – הראשונה ברשימת עשר המניות העולות של Yahoo Finance,
   בסגנון "מניית חברת תחום החלל אינטואיטיב מאשינס (Intuitive Machines) זינקה
   אמש בשבעה אחוזים ושתי עשיריות. זאת לאחר ש...", ומנגד מניה שצנחה בצורה
   קיצונית.
8. **אירופה ואסיה** – "באירופה, המסחר ננעל אמש בירידות שערים." ו"באסיה,
   המדדים המובילים ננעלו אמש במגמה דומה."

כל המספרים נכתבים במילים בעברית ומדויקים עד עשירית האחוז ("במחצית האחוז",
"באחוז ושתי עשיריות", "בשבעה אחוזים ושתי עשיריות", "ארבעה אחוזים ושבעים
ושתיים מאיות", "תשעים ואחד דולרים לחבית"). הניסוח מתחלף מיום ליום כדי שלא
יחזרו אותם משפטים, וכשיום המסחר הוא יום שישי נכתב "בסוף השבוע" במקום "אמש".
פסקת סקטורים (החזק והחלש מבין 11 סקטורי ה-S&P 500) קיימת אך כבויה כברירת
מחדל; מפעילים אותה עם `MIVZAK_INCLUDE_SECTORS=true`.

## מקורות

- נתוני שוק מאומתים לתאריך המסחר: Yahoo Finance (עם גיבוי מנתוני האוצר
  האמריקאי לתשואת האג"ח).
- חדשות מאותו יום בלבד: גלובס, TheMarker, כלכליסט, ביזפורטל, MarketWatch,
  Bloomberg, Yahoo Finance, Investing.com – דרך RSS, קריאת הכתבות המלאות
  וחיפוש (Tavily / Exa) המוגבל לאתרים האלה בלבד.
- פסקאות החדשות נכתבות על ידי Gemini מתוך המקורות בלבד, ועוברות בדיקה:
  מקורות מאותו יום, מספרים במילים, עברית/אנגלית בלבד, ללא משפטים כפולים.
  אם המודל או החיפוש אינם זמינים, המבזק נשלח עם פסקאות נתוני השוק המאומתות
  והמייל מציין זאת ב"הערות מערכת".

## הגדרה חד־פעמית (Secrets)

ב-GitHub: **Settings → Secrets and variables → Actions → New repository secret**

| Secret | חובה | הסבר |
| --- | --- | --- |
| `GMAIL_ADDRESS` | כן | כתובת ה-Gmail השולחת |
| `GMAIL_APP_PASSWORD` | כן | סיסמת אפליקציה של Gmail (לא הסיסמה הרגילה) |
| `GEMINI_API_KEY` | מומלץ | מפתח Google AI Studio לכתיבת פסקאות החדשות |
| `TAVILY_API_KEY` | מומלץ | חיפוש כתבות מאותו יום באתרים החסומים ל-RSS (כלכליסט, ביזפורטל, MarketWatch, Bloomberg) |
| `EXA_API_KEY` | לא | חיפוש משלים כשיש מעט תוצאות |

הנמען הקבוע מוגדר בקבצי ה-workflow (`MIVZAK_RECIPIENT`).

## הרצה ידנית

**Actions → Mivzak IBI - primary → Run workflow**, עם האפשרויות:

- `dry_run` – מכין את המבזק ואת קובץ ה-Word בלי לשלוח מייל. התוצר מצורף
  ל-run כ-artifact ומוצג גם ב-Summary של ה-run.
- `force_send` – שולח גם אם כבר נשלח מבזק על אותו יום מסחר.
- `trading_date` – תאריך מסחר ספציפי (למשל `2026-09-03`). ריק = יום המסחר
  האחרון שהסתיים בארה"ב.
- `recipient` – כתובת חלופית לבדיקה (ריק = HELLYBRACHA@GMAIL.COM).

## הרצה מקומית

```bash
pip install -r requirements.txt
python -m unittest discover -s tests            # בדיקות יחידה
python -m mivzak --self-test
python -m mivzak --offline --dry-run           # נתוני דוגמה, בלי רשת
python -m mivzak --dry-run --trading-date 2026-09-03   # נתונים אמיתיים, בלי מייל
```

הפלט נכתב לתיקייה `generated/` (קובץ ה-Word בשם "מבזק בוקר DD.MM.YYYY.docx",
`email.html` ו-`narration.txt`).
לשליחה אמיתית מקומית יש להגדיר את משתני הסביבה שבטבלת ה-Secrets.

## הערות תפעול

- אם ביום המסחר לא התקיים מסחר בוול סטריט (חג בארה"ב), המבזק מציין זאת
  במקום נתוני הנעילה.
- אם לא ניתן לאמת לפחות שתי פסקאות ליום המסחר, המבזק לא נשלח וה-run נכשל
  בכוונה, כדי שה-backup ינסה שוב עשרים דקות אחר כך.
- כדי לשנות את משפטי הפתיחה והסיום יש לעדכן גם את התבנית וגם את
  `mivzak/config.py`.
